# 문서 작성 스타일

Artifacty의 영어 문서는 ASD-STE100에서 착안한 스타일을 사용합니다. 한국어 문서에도 같은 명료성 원칙을 적용하되, 자연스러운 한국어 표현을 사용합니다. 이 문서는 편집 지침이며 ASD-STE100 준수를 주장하지 않습니다.

문장과 절차 작성 규칙을 일관되게 적용하세요. 의미를 더 정확하게 전달할 수 있다면 기술 용어를 사용하세요. 소개 문장은 자연스럽게 쓰세요. 프로젝트의 ‘75%’ 목표는 이런 균형을 뜻하며, 표준 준수 점수가 아닙니다.

## 영어 문서의 문장과 용어

- 한 문장에는 하나의 핵심 내용을 담으세요. 명료성이 좋아진다면 긴 문장을 나누세요.
- 책임을 구분해야 할 때는 관리자, 아티팩트 소유자, 사용자, 서버 등 주체를 밝히세요.
- 능동태를 우선 사용하세요. 주체를 알 수 없거나 중요하지 않으면 수동태를 사용하세요.
- 같은 개념에는 같은 용어를 사용하세요. UI 이름, API 필드, CLI 명령어를 정확히 맞추세요.
- artifact, MCP, webhook, CIDR 등 정착된 용어를 유지하세요. 익숙하지 않은 용어는 처음 사용할 때 설명하세요.
- 완전한 문장을 만드는 데 필요한 단어는 유지하세요. 설명문을 압축된 메모처럼 쓰지 마세요.
- 고정된 단어 수 제한을 강제하지 마세요. 제한된 사전에 맞추기 위해 정확한 용어를 바꾸지 마세요.

## 지시와 동작 설명

- 행동을 설명하기 전에 전제 조건과 적용 조건을 밝히세요.
- 번호가 있는 각 단계에는 하나의 행동을 담으세요. 그 행동을 수행하는 명령어 또는 UI 요소를 보여 주세요.
- 독자가 행동을 검증하는 데 필요하다면 예상 결과를 밝히세요.
- 기본값, 권한, 예외, 복구 동작을 명시하세요.
- 필수 사항과 권장 사항을 구분하세요. 명세에 나오는 MUST, SHOULD, MAY의 의미를 유지하세요.
- 설명문을 편집할 때 명령어, 식별자, URL, 예제, 기술적 제약을 유지하세요.
- 계획 중인 기능은 계획임을 밝히세요. 설계 제안을 현재 동작처럼 설명하지 마세요.

## 문서 유형에 따른 적용

설치 안내, API 참조, 보안 문서에는 이 규칙을 가장 엄격하게 적용하세요. README 소개, 설계 근거, 출시 글에서는 문장이 자연스럽게 이어지도록 설명해도 됩니다. 독자에게 필요한 설명은 유지하세요. 조건이나 예외를 생략한다면 짧은 글도 도움이 되지 않습니다.

영어 문서에서는 다음과 같이 씁니다.

> By default, share links do not work in private mode. An administrator must enable them in Access settings.

이 예문은 ‘비공개 모드에서는 기본적으로 공유 링크가 동작하지 않으며, 관리자가 접근 설정에서 활성화해야 한다’는 뜻입니다. 기본값, 책임 주체, 설정 위치를 명시합니다.

표준의 목적과 구성은 [공식 ASD-STE100 소개](https://www.asd-ste100.org/about.html)를 참고하세요.

## 한국어 문서 작성 기준

한국어 문서에도 같은 명료성 원칙을 적용합니다. 다만 영어의 문장 구조나 어휘 규칙을 그대로 옮기지 않고, 자연스러운 한국어 어순과 흐름을 살립니다. ‘75% 강도’는 편집 방향을 뜻하며, 표준 준수율을 뜻하지 않습니다.

- 한 문장에는 하나의 핵심 내용을 담습니다. 서로 밀접한 내용은 자연스럽게 연결하고, 짧게 쓰기 위해 문장을 지나치게 끊지 않습니다.
- 조건이나 전제는 행동보다 먼저 설명합니다. 절차는 단계별로 나누고, 필요한 경우 예상 결과와 확인 방법을 덧붙입니다.
- 권한이나 책임을 구분해야 할 때는 주체를 밝힙니다. 문맥상 분명한 주어는 반복하지 않습니다.
- 번역투, 불필요한 수동 표현, 명사만 나열하는 문장을 피합니다. 예를 들어 ‘설정의 변경이 가능합니다’보다 ‘설정을 변경할 수 있습니다’로 씁니다.
- 같은 개념에는 같은 용어를 사용합니다. 화면 이름은 해당 언어의 실제 UI 표기와 맞추고, 명령어·API 필드·코드 식별자는 그대로 유지합니다.
- 익숙한 기술 용어는 억지로 번역하지 않습니다. 설명이 필요한 용어는 처음 나올 때 간단히 풀이합니다.
- 기본값, 예외, 제한, 복구 조건을 생략하지 않습니다. 필수 사항과 권장 사항도 명확히 구분합니다.
- 설명문은 ‘합니다’체를 기본으로 씁니다. 절차에서는 필요한 행동을 ‘선택하세요’, ‘실행하세요’처럼 직접 안내합니다.

예를 들어 다음과 같이 씁니다.

> 비공개 모드에서는 기본적으로 공유 링크를 사용할 수 없습니다. 관리자가 접근 설정에서 공유 링크를 허용해야 합니다.

설치·API·보안 문서에는 이 기준을 엄격하게 적용합니다. 소개 글과 설계 배경에서는 정확성을 유지하면서 문장이 자연스럽게 이어지도록 씁니다.
